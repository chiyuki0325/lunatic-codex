# `/context` 上下文窗口占用查看

这是 Codex「月狂氛围」的特性开发分支，基于上游 **v0.149.1**。

无前置特性分支；本特性基于 `lunatic/template-v0.149.1` 独立开发，之后可与异步命令、中文化等特性移摘组合。

> 对于任何编码智能体：当在 Linux arm64 平台上开发时，禁止本机编译（本机性能不足，编译 Codex 需要至少 32G 内存），必须参考 `building-codex-in-devbox.txt` 在远端开发机编译。

## 目标

增加本地斜杠命令 `/context`，用一张可视化占用图展示当前主会话实际送入模型的上下文窗口、各来源的估算 Token 占用、自动压缩预留区和剩余空间。用户应能快速判断上下文是否接近上限，以及固定提示词、工具定义、指令文件、Skills、MCP 工具或会话消息中哪一类占用较大。

命令是只读诊断操作，不启动模型 turn，不向会话注入消息，也不修改上下文、配置或压缩状态。

## 用户体验

### 命令入口

- 在斜杠命令列表中增加 `/context`，描述为查看当前上下文窗口占用。
- 命令无参数，结果作为持久的历史单元插入当前会话，能够随终端滚动并进入 scrollback。
- `/context` 在空闲、agent 工作中、工具调用中、会话启动和 MCP 初始化期间均可立即执行；不得等待当前 turn 结束，也不得中断或 steer 当前 turn。
- 连续执行 `/context` 时，每次生成一个独立快照；已有快照不随之后的 Token 更新原地变化。

### 主视图

结果至少包含：

1. 标题 `上下文用量`。
2. 当前模型名。
3. 顶部总览：最近一次 API 返回的实际上下文用量、模型上下文窗口上限、占用百分比和剩余百分比。
4. 彩色字符网格：直观表示各互斥分类、自动压缩预留区和剩余空间。
5. 分类图例：每项展示名称、估算 Token 数和占整个模型窗口的百分比，并明确使用 `各分类估算用量` 表述估算性质。
6. 可定位明细：仅在存在对应内容时，展开 MCP 工具、指令文件和 Skills；每项显示名称或路径及估算 Token 数。
7. 数据新鲜度说明：运行中取一致性快照；顶部实际值来自最近一次已完成的 API 用量，当前请求尚未得到 API 结果时应标明实际值的来源时点。

本功能的所有用户可见文案使用简体中文；命令、模型名、文件名、工具名、配置/协议标识和 `Token` 等技术术语保持原文。

概念效果如下，具体颜色和间距遵循 `codex-rs/tui/styles.md`，窄终端允许调整网格列数和左右布局：

### 自适应布局

- 宽度足够时，网格与图例左右排列；宽度不足时改为上下排列或缩短网格列数，内容不得被硬截断。
- 默认网格固定为 `10 × 10`，共 100 个格子，每格代表模型上下文窗口的 1%；超大窗口仍使用 `10 × 10` 的百分比网格。仅在终端宽度无法容纳时允许改变排列方式，不得减少格子总数。
- 格子分配按最大余数或等价的确定性方法取整，最终格子总数必须固定；非零小分类应尽量至少可见一个格子，且不得导致总格数溢出。
- 所有宽度计算使用 Unicode display width；快照覆盖窄终端和常规终端。
- 普通固定分类使用 `⛁`，不足一格的部分占用使用 `⛀`；消息分类在图例和网格中使用实心块 `■`；自动压缩预留区使用 `⛝`，剩余空间使用 `⛶`。颜色与字符共同编码分类，保证无色终端中仍可读。

## 统计口径

### 顶部实际总量

- 首选会话最近一次模型响应携带的实际 Token 用量，沿用 Codex 已有 token usage 数据源，避免 `/context` 与状态栏对同一轮上下文给出不同的“真实总量”。
- 模型窗口上限使用该请求实际生效的模型配置，不硬编码具体模型大小。
- 首次模型响应之前没有 API 实际值时，顶部使用当前请求视图的本地估算，并显式标为 `估算`；不得显示伪造的 0 Token 实际值。
- 运行中的新请求尚未返回用量时，顶部保留最近一次实际值并标明它属于上一份已完成请求；分类和明细仍按命令执行时的当前请求快照计算。

### 分类估算

分类互斥，禁止把同一段内容同时计入多个一级分类。首版用户可见分类为：

- `系统提示词`：Responses API 请求中的基础 instructions。
- `内置工具`：当前请求实际向模型公开的内置工具定义。
- `MCP 工具`：当前请求实际向模型公开的 MCP 工具定义；按工具提供明细。按需加载但尚未公开给模型的工具可在明细中标为 `可用` 或 `延迟加载`，但不计入窗口占用和网格。
- `指令`：当前请求中的开发者指令、用户指令、适用的 `AGENTS.md` 及其他非 Skill 的上下文指令；可定位文件按文件提供明细。
- `Skills`：当前请求实际注入的 Skill 元数据或正文；按 Skill 提供明细。仅可用但未注入的 Skill 不计入占用。
- `消息`：上述固定上下文之外，实际发送的用户消息、assistant 消息、推理摘要、工具调用、工具结果、附件及压缩摘要。
- `其他`：只用于无法可靠归入上述来源的实际请求内容；正常路径应尽量为空，但不得为了让分类之和好看而错误归类。

估算复用 Codex 现有的请求序列化结构和 Token 近似工具，按模型真正可见的文本、JSON 和图片成本计算，不从 TUI 显示文本反推，不重新扫描一份可能已经过期的原始聊天记录。

### 实际总量与分类差值

- 顶部 API 实际值是权威总量，分类值保持本地估算，不按比例伪装成精确值。
- 当 API 实际总量与分类估算和相差时，网格增加 `未归因` 差值分类以对齐实际已用总量；图例说明该项是 API 计数与本地估算之间的差额。
- 若分类估算高于 API 实际总量，不产生负数空闲区；显示估算偏差提示，并以 API 实际值计算总占用与剩余空间。
- 百分比以完整模型上下文窗口为分母，保留一位小数；顶部使用量和状态栏的取整语义保持一致。

### 自动压缩预留区与空闲区

- `自动压缩预留区` 来自当前模型和当前配置实际使用的自动压缩阈值，不复制魔数。
- 自动压缩未启用或当前策略没有固定预留区时，不显示虚假的预留分类。
- `剩余空间` 使用模型窗口上限减去 API 实际已用量和当前策略的固定预留量，最小为 0。
- 预留区不计入顶部“实际已用 Token”，但在网格中占据独立空间，让用户看到真正可继续使用的安全余量。

## 一致性与并发

- Core 在请求边界保存轻量、只读的上下文计数快照；快照与对应的模型、工具路由、上下文历史版本和自动压缩阈值绑定。
- `/context` 读取快照时不得持有会阻塞流式响应、工具调用或输入处理的长生命周期锁。
- agent 工作中优先读取当前 active turn 最近一次已构造请求的快照；若该 turn 尚未构造请求，则从 active turn 的已捕获配置生成只读快照。
- 空闲时使用下一 turn 将采用的当前线程设置生成快照，因此 `/model` 等设置变更完成后再次执行 `/context` 应反映新设置。
- 统计过程不得触发 MCP 重连、工具调用、模型请求、上下文压缩、历史重写或新的 rollout 消息。
- 在统计期间上下文继续变化时，输出仍保持内部一致，并标识快照版本或时间；不得混用不同请求版本的分类明细。

## 实现设计

### Core 侧

- 在靠近实际请求构造的位置生成结构化 `ContextUsageSnapshot`，直接复用该请求的 `Prompt.input`、`Prompt.base_instructions`、model-visible tool specs、模型窗口与自动压缩阈值。
- 一级分类在请求组装阶段保留来源信息或建立独立的计数 sidecar；不得修改模型可见历史内容，也不得为统计重写上下文。
- 工具定义按最终发送到 Responses API 的序列化形态估算。Tool Router 同时提供内置/MCP 来源与 loaded/deferred 状态，避免通过工具名猜测来源。
- 会话历史使用现有 `ContextManager` 的模型可见视图和图片/工具结果估算逻辑；压缩后只计算真正保留的历史。
- 指令文件和 Skills 的明细在现有上下文贡献者渲染时记录来源与估算值；一级分类只统计最终实际注入的内容。
- 最近 API 实际用量继续来自现有 `TokenUsageInfo`，快照只引用或复制数值，不建立第二套累计器。

### 协议与 app-server

- TUI 当前通过 app-server 驱动线程，因此增加只读的 v2 `thread/contextUsage` 请求，由 app-server 转发到目标 Core session 并返回结构化快照。
- 请求参数使用 thread id；响应包含模型、窗口、实际用量及来源状态、分类、明细、预留量和快照标识。
- 该接口不写 rollout，不生成普通 thread item，也不改变 turn 状态；并发查询只读取一致性快照。
- 新协议类型遵循 v2 camelCase、TypeScript 导出和 schema 生成规则；同步更新 app-server API 文档与 schema fixture。
- 若实现阶段发现已有内部请求通道能够满足 TUI 且无需新增公共 API，应优先复用；不得为单个 TUI 命令复制 Core 的请求构造逻辑。

### TUI 侧

- `SlashCommand` 增加 `Context`，命令在任务进行中和启动阶段保持可用。
- 命令派发后异步请求快照；请求期间插入或更新显示 `正在统计上下文用量…` 的历史单元，不冻结 composer。
- 成功后用独立 history cell 渲染网格、图例和明细；失败时将同一单元更新为简体中文错误，保留继续输入能力。
- 渲染实现放入新的小模块，避免继续扩大 `chatwidget.rs`、`app.rs` 等高触达大文件。
- 颜色使用 Ratatui `Stylize` 辅助方法，不硬编码白色；普通文本使用默认前景色。

## 错误与边界情况

- 线程尚未完成配置时，若已有足够信息生成估算快照则正常展示；否则显示 `暂时无法获取上下文用量`，不得 panic。
- 模型窗口未知时仍可展示各分类 Token 数和明细，但隐藏百分比、网格、剩余空间与预留区，并明确窗口未知。
- 无历史消息时仍显示固定上下文、工具定义和空闲空间。
- MCP 未配置、无指令文件或无 Skills 时省略对应明细段，不显示空标题。
- 单个名称或路径超过终端宽度时按现有 wrapping 工具换行；不得破坏其他行对齐。
- API 查询失败、线程切换或目标线程关闭时显示局部错误，不退出 TUI，也不影响正在运行的 turn。
- `/context` 输出本身是本地 UI 结果，不得加入下一次模型上下文或影响之后的 Token 统计。

## 非目标

- 不提供非交互 CLI 或 SDK 的 context-usage 输出。
- 不自动执行 `/compact`，不自动禁用工具、MCP、Skills 或指令文件。
- 不改变现有自动压缩阈值、压缩算法、状态栏百分比算法或模型请求内容。
- 不提供逐条消息、逐个内置工具或内部系统提示词分段的调试级明细。
- 不把按需可用但尚未加载的工具计入当前窗口占用。
- 不为获得精确分类额外调用模型提供商的 Token 计数 API。
- 不扩展到整个 TUI 的中文化；只要求 `/context` 命令描述、加载态、结果和错误等本功能新增的用户可见文本使用简体中文。

## 验收条件

- `/context` 出现在命令列表，中文描述清楚表达其用途；执行后无需模型请求即可显示当前主线程快照。
- 本功能新增的标题、状态、分类、明细、提示和错误全部使用简体中文；命令、模型名、文件名、工具名、配置/协议标识和 `Token` 等技术术语保持原文。
- 空闲、agent 流式响应、工具调用、会话启动和 MCP 初始化期间执行命令均不会阻塞当前工作或 composer。
- 有 API 用量时，顶部实际 Token 总量与同一轮现有状态栏数据一致；无 API 用量时明确显示估算值。
- 分类值互斥；默认网格严格为 `10 × 10`、共 100 格，实际占用、`未归因`、预留和空闲最终覆盖整个窗口，不出现负数或格子溢出。
- 系统提示词、内置工具、MCP 工具、指令、Skills、消息、自动压缩预留和空闲空间按当前请求与配置正确出现或省略。
- deferred MCP 工具不计入窗口；加载后再次执行命令会反映到占用分类和明细。
- `/compact`、模型切换、Skill 注入、MCP 工具加载或适用 `AGENTS.md` 变化后，新快照反映新的模型可见上下文，旧快照保持不变。
- 模型窗口未知、首次响应前、空会话、无 MCP、无 Skills、窄终端和查询失败均有覆盖。
- UI 变化有常规宽度与窄宽度 `insta` snapshots；Core 分类、差值对齐、预留区和并发快照有行为测试；app-server 请求有公开 JSON-RPC 集成测试。
- 本地只运行格式化、静态检查和无需编译的检查；Rust 编译、`just fix -p codex-tui`、`just test -p codex-tui` 及受影响 crate 测试按 `building-codex-in-devbox.txt` 在远端开发机完成，并分别报告结果。
