# 界面全部中文化

这是 Codex「月狂氛围」的特性开发分支，基于上游 **v0.149.1**。

前置需求：无。

## 详细需求

### 目标

将 `codex` 启动后的交互式 TUI 固定为简体中文，使 Codex 自身提供的界面、操作提示和面向用户的运行状态不再混用英文。不增加语言配置、系统语言检测或运行时语言切换能力。

### 覆盖范围

- 启动、欢迎、登录、目录信任和首次使用流程。
- 输入框、底栏、快捷键提示、斜杠命令说明和命令补全面板。
- 模型、推理强度、权限、主题、状态栏、插件、MCP、Skills、Apps、实验功能等选择器和设置界面。
- 命令审批、网络审批、文件变更审批、用户提问及其结果反馈。
- 会话历史中的 Codex 状态、工具执行状态、计划、补丁、搜索、Hook、MCP 和多agent等由程序生成的标签与说明。
- `/status`、用量和用量限制、会话恢复与管理、更新提示、通知、警告、错误及其他 TUI 弹窗或状态页。
- 由 `codex-core` 或 app-server 生成并最终展示在 TUI 中的用户提示，应在其源头翻译。允许这些共享文本在 `exec` 或其他客户端中也显示为中文，但不得改变协议结构、事件类型或字段语义。

以下内容不在本特性的主动翻译范围内：

- `codex --help`、`codex exec`、doctor、app-server 等非交互界面自身的专用文案。
- 模型回复、用户输入、代码、路径、Git 或 shell 输出、MCP/Hook/插件等外部组件返回的内容。
- tracing 日志、开发调试信息、测试名称、代码注释及仅供内部使用的错误上下文。

当 Codex 自身的中文提示包含外部错误时，只翻译 Codex 添加的上下文，保留外部错误原文，避免破坏诊断信息。

### 翻译规则

- 使用自然、简洁的简体中文和中文标点，不按英文词序机械拼接句子。
- 保留用户必须原样输入或识别的标识符，例如 `/model`、命令行参数、配置键、环境变量、文件名和协议字段。
- 保留按键名及组合键，例如 `Esc`、`Enter`、`Tab`、`Ctrl+C`。
- 保留产品名和常用专名，例如 Codex、OpenAI、ChatGPT、MCP、IDE、Token、Hook、Skills、Apps、AGENTS.md；其余技术概念采用自然中文译名。
- 不改变快捷键、命令解析、审批语义、状态机、协议载荷或错误传播行为。
- 中文字符通常占两个终端列，任何翻译都不得按字符数代替终端显示宽度；继续使用现有的 Unicode 宽度、换行和截断工具，不自行用 `str::len`、字节数或字符数计算布局。
- 改动表格、弹窗、选择器、底栏等紧凑布局时，必须同时检查常规宽度与窄终端，避免中文导致边框错位、内容覆盖、提前截断或按键提示消失。

### 术语表

同一概念在标题、正文、状态标签和操作提示中采用下列统一译法；可按中文语法调整词序，但不得另造同义译名。

| 上游术语 | 统一译法 | 使用说明 |
| --- | --- | --- |
| agent | agent | `subagent` 保留为“subagent”；`multi-agent` 译为“多agent”。 |
| conversation / side conversation | 对话 / 平行对话 | 强调可恢复、归档或删除的持久记录时使用“会话”。 |
| session | 会话 | 用于会话恢复、重命名、归档、删除、配置和用量等界面。代码或协议中的 `thread`、`thread_id` 等标识符保持原样。 |
| model | 模型 | `model migration` 译为“模型迁移”。模型 ID 和供应商给出的模型名称保持原样。 |
| reasoning effort | 推理强度 | 不使用“推理努力程度”等机械直译。 |
| approval | 审批 | 名词和流程使用“审批”；按钮或动作可按语境使用“批准”。 |
| permission | 权限 | 与“审批”区分，表示已配置或授予的能力范围。 |
| sandbox | 沙箱 | 权限级别和运行环境名称中的固定标识符保持原样。 |
| plugin | 插件 | 官方功能名或界面栏目 `Plugins` 保持原样时，不再翻译。 |
| Skill | Skill | `Skill` 保留原样；官方功能名或界面栏目 `Skills` 也保持原样。 |
| app / desktop app | 应用 / 桌面应用 | 官方功能名或界面栏目 `Apps` 保持原样时，不再翻译。 |
| tool | 工具 | 工具活动的进行、完成、失败和汇总状态均使用这一译法。具体工具名保持原样。 |
| web search | 网页搜索 | 搜索词、URL 和搜索服务返回的内容保持原样。 |
| patch | 补丁 | 文件路径、diff 内容和 Git 输出保持原样。 |
| context window | 上下文窗口 | 涉及计量时使用“上下文窗口大小”“已用 Token”等表达。 |
| usage / rate limit | 用量 / 用量限制 | 账户用量、用量限制、重置时间和限制状态采用这一组表达。 |

#### 应保留原样的术语和文本

| 类别 | 保留内容与示例 |
| --- | --- |
| Token 术语 | 始终写作 `Token`，不译为“令牌”，也不在中文文案中写作小写 `token`；使用“Token 用量”“输入 Token”“输出 Token”“Token 预算”和 `Bearer Token` 等形式。 |
| 产品名与专名 | Codex、OpenAI、ChatGPT、MCP、IDE、Skills、Apps、AGENTS.md、Hook、Git、Markdown。可在其后添加中文说明，如“MCP 服务器”“Hook 审核”。 |
| 命令与参数 | 斜杠命令、命令行命令及其参数保持原样，例如 `/model`、`/mcp verbose`、`--full-auto`。 |
| 配置与环境标识 | 配置键、环境变量、模型 ID、工具名、文件名和路径保持原样，例如 `approval_policy`、`CODEX_HOME`、`gpt-5`、`AGENTS.md`。 |
| 协议标识 | 协议名称、事件类型、字段名和字段值保持原样，例如 `thread_id`、`rawResponseItem`、`type`。 |
| 按键绑定语法 | 按键名、组合键和绑定写法保持原样，例如 `Esc`、`Enter`、`Tab`、方向键、`Ctrl+C`、`Ctrl+Shift+P`。 |
| 外部内容 | 用户输入、模型回复、代码、URL、Git 或 shell 输出，以及 MCP、Hook、插件和其他外部组件返回的正文与诊断详情。Codex 自己添加的上下文仍应翻译。 |

保留原样只适用于术语、标识符和外部内容；其周围由 Codex 生成的标题、状态、说明、按钮和错误上下文仍使用简体中文。

### 验收标准

- 从首次启动、登录到进入对话的正常路径中，Codex 自有界面文案均为简体中文。
- 常用命令面板、设置选择器、审批流程、状态与用量页面、会话管理及更新流程均无未约定的静态英文文案。
- 正常对话、工具执行、失败、警告和取消等代表性历史记录均使用中文程序文案，外部内容保持原样。
- `/model` 等命令名、按键名、产品名和其他保留标识符仍与上游兼容。
- 现有用户可见 UI 的 `insta` 快照随翻译更新，并为缺少覆盖的主要流程补充代表性快照；涉及换行、截断、表格、弹窗、选择器或底栏的界面至少覆盖一个窄终端场景，并人工核对边框与列宽。
- `just test -p codex-tui` 通过；若修改共享的 core 或 protocol 代码，还应运行对应 crate 测试，并在获得许可后运行完整 `just test`。

## 开发记录

### 需求分析

- 当前代码库没有 i18n 框架或集中式语言资源，用户可见文案主要以 Rust 字符串字面量直接分散在各界面模块中。本特性采用固定简体中文，不引入新的本地化抽象。
- TUI 主要排查位点包括 `codex-rs/tui/src/onboarding/`、`bottom_pane/`、`history_cell/`、`status/`、`chatwidget/`、`app/`，以及 `slash_command.rs`、`keymap.rs`、会话选择器和更新相关模块。
- app-server 通知中的部分错误文本会作为普通字符串透传给 TUI，例如 `codex-rs/tui/src/app/app_server_events.rs`。这类 Codex 自有提示需要追溯到 core/app-server 的产生位置翻译，而不是在 TUI 中按英文原文建立脆弱的字符串映射。
- TUI 已有大量快照覆盖。翻译会改变可见宽度和换行，实施时必须逐个审阅相关 `*.snap.new`，不能仅批量接受快照。
